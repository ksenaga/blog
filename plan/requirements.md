## 1. システムの目的

| 項目 | 内容 |
|---|---|
| 目的 | ブログを表示するサイトと、ブログを管理するCMSを作成する |

## 2. 利用者

| 利用者 | 説明 | ログイン |
|---|---|---|
| 閲覧者 | ブログを閲覧する人 | ✕ |
| ユーザー | 自分のブログを更新する人 | ○ |

## 4. ブログ（閲覧側）が持つ情報

| 項目 | 説明 |
|---|---|
| 公開日時 | ブログを公開した日時（作成日時ではなく公開日時を表示する） |
| 更新日時 | 公開日と違う日に更新した場合のみ表示する |
| タイトル | ブログのタイトル |
| 本文 | ブログの本文 |
| 画像 | 本文中の画像（1記事に10枚程度） |
| 作者 | ブログを作成したユーザー |

## 5. ブログ（管理側）が持つ情報

| 項目 | 説明 |
|---|---|
| 作成日時 | ブログを作成した日時 |
| 更新日時 | ブログを最後に更新した日時 |
| 公開日時 | ブログを公開した日時（公開予定の場合は予定日時） |
| タイトル | ブログのタイトル |
| 本文 | ブログの本文 |
| 画像 | 本文中の画像 |
| 作者 | ブログを作成したユーザー |
| ステータス | 下表のいずれか |
| ユーザー情報 | 作者の情報 |

| ステータス | 値 | 説明 |
|---|---|---|
| 下書き | `draft` | 作成中。閲覧者には見えない |
| 公開予定 | `scheduled` | 指定した日時に公開される |
| 非公開 | `private` | 一度公開したものを非公開にした状態 |
| 公開 | `public` | 閲覧者に公開している状態 |

## 6. 権限

凡例：○ = 可 / ✕ = 不可

| 操作 | 管理者 | ユーザー | 閲覧者 |
|---|---|---|---|
| ログイン | ○ | ○ | ✕ |
| ユーザーの作成 | ○ | ✕ | ✕ |
| ユーザーの閲覧・編集・削除 | ○（全ユーザー） | ○（自分のみ） | ✕ |
| ユーザーのロール変更 | ○ | ✕ | ✕ |
| パスワードのリセット | ○ | ✕ | ✕ |
| ブログの作成 | ○ | ○ | ✕ |
| ブログの閲覧・編集・削除 | ○（全ブログ） | ○（自分のブログのみ） | ✕ |
| ブログの閲覧（公開中のもの） | ○ | ○ | ○ |

| 補足 |
|---|
| 管理者が他のユーザーのブログを操作した場合は、操作ログを記録し、そのユーザーのダッシュボードに通知する |
| 閲覧者はDB上にロールを作らない |

## 7. 業務ルール

### 7-1. 公開の流れ

| 順番 | 内容 |
|---|---|
| 1 | ユーザーがブログを作成する（下書き） |
| 2 | ユーザーが自分でステータスを「公開」または「公開予定」に変更する |

### 7-2. ステータス遷移

| 現在 \ 変更先 | 下書き | 公開予定 | 公開 | 非公開 | 削除 | 編集 |
|---|---|---|---|---|---|---|
| 下書き | - | ○ | ○ | ✕ | ○ | ○ |
| 公開予定 | ✕ | - | ○ | ○ | ○ | ○ |
| 公開 | ✕ | ✕ | - | ○ | ✕ | ✕ |
| 非公開 | ✕ | ○ | ○ | - | ○ | ○ |

### 7-3. 公開中のブログの編集

| ルール |
|---|
| 公開中のブログを編集するときは、一度非公開に変更する |
| 非公開にしても、いいね数とコメントの内容は維持する |
| シェアしたURLが変わらないよう、非公開にしても同じURLを使う |
| 非公開のURLにアクセスした場合は、「現在は非公開中です」という画面を表示する |

### 7-4. URL

| 対象 | URL |
|---|---|
| ブログ詳細 | `/blog/{slug}`（slug はUUID） |

### 7-5. 削除

| ルール |
|---|
| 削除したブログは、削除一覧で閲覧・復活できる |
| 管理者が削除したブログも、削除一覧で閲覧・復活できる |
| ユーザーを削除した場合は、そのユーザーのブログも削除する |

### 7-6. 認証

| 項目 | 内容 |
|---|---|
| ログイン方式 | JWT で管理する |
| パスワードを忘れた場合 | 管理者がリセットする |

## 8. 非機能要件

| 分類 | 要件 |
|---|---|
| 言語 | 日本語のみに対応する |
| 画面 | レスポンシブ対応にする |
| 画像 | 1記事に10枚程度の画像を使うため、PNG・JPGはWebPに変換する |
| 通信 | 全ての通信をHTTPSにする（HTTPはHTTPSへリダイレクトし、HSTSを付ける） |
| セキュリティ | API はフロントと同じオリジンで提供し、他のオリジンからのリクエストは許可しない（CORS の設定はしない） |
| セキュリティ | ログイン試行回数を制限する（5回失敗で15分ロック） |

## 10. 決定事項

要件定義の確認で決まった事項。変更する場合は各設計書もあわせて修正する。

| No | 項目 | 決定内容 |
|---|---|---|
| 1 | 公開中ブログの削除 | 直接削除できない。非公開にしてから削除する |
| 2 | 公開予定 | 公開日時（`published_at`）を必須とする。公開日時を過ぎたものは、取得時の判定と定期バッチの両方で公開として扱う |
| 3 | 復活後のステータス | 一度でも公開したことがあれば「非公開」、なければ「下書き」に戻す |
| 4 | ユーザー削除時 | ユーザーは論理削除し、そのユーザーのブログは削除一覧へ移す。そのブログは復活できない |
| 5 | slug | ブログ作成時にUUIDを自動生成する。変更はできない |
| 6 | 未公開ブログのURL | 一度も公開していないブログ（下書き・公開日時前の公開予定・公開前に非公開にしたもの）のURLは404とする |
| 7 | JWT | アクセストークン15分（Bearer）、リフレッシュトークン14日（httpOnly Cookie、DB管理） |
| 8 | 本文の形式 | リッチエディタ（TipTap）で編集し、JSON で保存する。表示時に HTML へ変換し、サニタイズする（書く人がエンジニアではないため） |
| 9 | 同時編集 | 楽観的ロック（`version`）で上書きを防ぐ |
| 10 | 画像 | 1枚最大10MB、1記事最大20枚。アップロード時にWebPへ変換し、EXIFを削除する。上限値は設定で変更できる |

## 11. 技術構成

### 11-1. 使う技術

| 分類 | 技術 | 用途・補足 |
|---|---|---|
| フロントエンド | Next.js（App Router）・TypeScript | `frontend/`。閲覧側と管理側（CMS）の画面 |
| バックエンド | Next.js（API専用）・TypeScript | `backend/`。Route Handlers（`app/api/v1/...`）だけを使う |
| 接続方法 | Next.js の rewrites | ブラウザは frontend にだけアクセスし、`/api/v1/*` は frontend が backend へ転送する。ブラウザからは同じオリジンに見えるため、CORS の設定は不要 |
| DB | PostgreSQL 16 | |
| ORM・マイグレーション | Prisma | スキーマとマイグレーションを管理する |
| リッチエディタ | TipTap（無料の拡張機能のみ） | 本文の編集 |
| 画像の保存先 | ローカル：Docker のボリューム / 本番：S3 互換ストレージ | 環境変数 `STORAGE_DRIVER` で切り替える（MinIO は公式の Docker イメージが取得できなくなったため使わない） |
| 実行環境 | Docker / Docker Compose | ローカルでの動作確認 |

### 11-2. 主なライブラリ（予定）

| 用途 | ライブラリ |
|---|---|
| 画像の変換（WebP 化・EXIF 削除・縮小） | sharp |
| 画像の保存（本番の S3） | @aws-sdk/client-s3 |
| JWT の発行・検証 | jose |
| パスワードのハッシュ化 | bcrypt |
| 入力チェック | zod |
| 本文 JSON から HTML への変換 | @tiptap/html |
| HTML のサニタイズ | sanitize-html |
| 定期バッチ | node-cron |

### 11-3. Docker のコンテナ構成（ローカル）

| コンテナ | 内容 | ポート |
|---|---|---|
| `frontend` | Next.js（画面） | 3000 |
| `backend` | Next.js（API）。Prisma もここで管理する | 4000（動作確認用） |
| `db` | PostgreSQL 16 | 5432 |
| `worker` | 定期バッチ（公開予定の公開、未使用画像の削除など）。`backend` と同じコードを使う | - |

### 11-4. 画像の保存先の切り替え

| 項目 | 内容 |
|---|---|
| 考え方 | DB には保存先のパス（`storage_key`）だけを持ち、画像URLは「`IMAGE_BASE_URL` + `storage_key`」で組み立てる |
| ローカル | Docker のボリューム（`uploads`）に保存し、`/uploads/{storage_key}` で配信する（frontend が backend へ転送する） |
| ローカル → 本番 | ① 画像ファイルを同じパスのまま本番のストレージへコピーする（`aws s3 sync` など） ② 環境変数（`STORAGE_DRIVER=s3`・`IMAGE_BASE_URL` など）を本番用に変える。DB の変更は不要 |
